PlayStation game Shaman King: Spirit of Shamans (Bandai, Japan 2002, SLPS-03432; PsyQ SDK, GCC for MIPS R3000). FILE is the decompile of either the main executable SLPS_034.32 (loaded at 0x80010000-0x800c27ff, bss to 0x800cad88) or one overlay PROG\O_*.PRG (O_MINI minigame, O_TRAIN training, O_STORY story, O_OPTION options, O_MOVIE movie player) loaded at 0x800cad88; overlay calls below 0x800cad88 go into the main exe. Files come from a packed archive SOUL.BIN indexed by SOUL.FAT (16-byte entries name[12] + sector<<12|size) with paths like SYS\SYSTEM.XAP, SELECT\TITLE.XAP, MDI\BGM%02d.SEQ, ICON\ICON%02d.XAP, per-character .AO files. Research only. Game: anime action/fighting game where shamans fight with a guardian spirit (over soul: spirit fused into a weapon, furyoku = spirit power meter), story mode, training, minigame, memory card saves. Expect: GTE-heavy 3D transform/draw code, sprite 2D UI, pad reading, CD streaming + XA audio, SEQ/VAB music, character state machines (idle, move, attack, guard, hit, knocked down, spirit attacks), hit detection, meters, AI opponents, camera, menus, story text/scripts.
Names already given (biosA0_*, biosB0_*, biosC0_* = BIOS call stubs from the public psx-spx tables; stub_/retN_) are trusted. Some blocks carry a "/* decider hint: ... */" line: hw= hardware blocks touched (cdrom 0x1f801800, gpu 0x1f801810/14, mdec, spu 0x1f801c00.., dma 0x1f801080.., timer 0x1f801100.., irq 0x1f801070/74, sio = pad/memory card 0x1f801040..), gte=N = count of GTE (cop2) instructions, cop0=N, str= strings. Use them.

Task: name functions from the Ghidra decompile. FILE holds the decompile of a slice of the functions. Name EVERY function in FILE whose name is still FUN_xxxxxxxx (skip ones that already have a name).

Evidence to use: strings, called functions, PSX hardware registers, GTE ops (RotTransPers / RotMatrix / MulMatrix / NormalClip / AverageZ style PsyQ libgte functions), GPU primitive packets (OT linking: addPrim, ClearOTag, DrawOTag, SetPolyFT4 etc. by the code byte written at +7: 0x20 POLY_F3, 0x24 POLY_FT3, 0x28 POLY_F4, 0x2c POLY_FT4, 0x30 POLY_G3, 0x34 POLY_GT3, 0x38 POLY_G4, 0x3c POLY_GT4, 0x40 LINE_F2, 0x64 SPRT, 0xe1.. draw mode settings), libcd (CdInit, CdControl, CdRead, CdSync, CdReadSync, CdSearchFile, CdIntToPos, CdPosToInt), libgpu (ResetGraph, SetDispMask, PutDrawEnv, PutDispEnv, DrawSync, VSync, LoadImage, StoreImage, MoveImage, ClearImage, GetTPage, GetClut), libetc (PadInit, VSync, VSyncCallback, ResetCallback), libspu / libsnd, libcard / libmcrd, libapi (EnterCriticalSection, OpenEvent wrappers), libc (sprintf, printf, memcpy, rand). Only use a PsyQ API name when the behaviour clearly matches (say why in the comment); otherwise give a descriptive name. Fixed point: 4096 = 1.0 (ONE), angles 4096 = 360 degrees, rsin/rcos tables.

Naming style: lowercase module prefix + CamelCase verb, e.g. gpu_AddPolyFT4, cd_ReadSectors, pad_Read, plyr_UpdateState, spirit_StartOverSoul, hit_CheckAttackBox, menu_DrawCursor, math_FixedMul, mem_Copy. PsyQ library functions keep their SDK name (CdRead, DrawSync, RotTransPers). Tiny stubs that only return: stub_<addr>. Data mistaken for code: data_<addr>. When unsure, still give the best descriptive name and add "provisional" at the start of the comment.

Output: write lines to OUT (create it with Write; one line per function, no other text):
0x<addr> func <name> hand <comment of 5-20 words: what it does, key callees, registers or strings>
Addresses as 8 lowercase hex digits (e.g. 0x8002c244). Names must be unique within OUT; append _2, _3 when two functions would share a name. Do not read files other than FILE. Read FILE in pieces (offset/limit, about 600 lines at a time) until the end. Reply at the end with only the line count.

Rule: name every function by reading its code yourself. Never generate names with a script or by pattern; generic shape-only names are not acceptable. Do not create helper files.
